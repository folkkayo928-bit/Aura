# Multichain wallet acceptance checklist

## Required for each of Ethereum, BNB Smart Chain, Solana, and TON
- [ ] Official Tether token identifier and decimals independently verified.
- [ ] Receive address generated by the intended wallet model and validated for that network.
- [ ] Incoming USDT transfer discovered and linked to the correct user.
- [ ] Same transaction/event replayed multiple times credits no more than once.
- [ ] Pending/confirming/confirmed states follow that chain's finality policy.
- [ ] Reorg, dropped transaction, provider timeout, and RPC failover do not create a false balance.
- [ ] Send path uses integer base units and correct decimals (never floating-point arithmetic for settlement).
- [ ] Invalid destination, unsupported token, insufficient native gas, and insufficient token balance fail safely.
- [ ] A broadcast timeout is reconciled by transaction hash before retrying.
- [ ] External wallet addresses require signed proof of control before being associated with an account.
- [ ] Seed phrases/private keys never leave the intended local wallet/key-management boundary.
- [ ] Public clients cannot insert, update, or delete event, address, ledger, or registry records directly.
- [ ] Browser, Telegram WebView, and mobile regression tests pass.
- [ ] Existing P2P escrow, withdrawals, internal transfers, Telegram notifications, and NFT ownership remain unchanged until cutover approval.
